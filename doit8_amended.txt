Дополненная директива слота E (исходник: doit8.txt). Изменения отмечены [ИЗМ] и [ДОБ].

П1 (ядро вахты): bptrace v2 — время на функцию, а не только вызовы.
[ИЗМ] Формулировка «время копим только при глубине 0» неточна: чтобы получить
self-время у ВЛОЖЕННЫХ функций, таймить нужно каждый вызов (стек в thread-local:
слот, старт, накопитель детей), а «глубина 0» касается лишь семантики детей:
total вызова целиком уходит родителю в children; self = total − children.
Глубина ограничена (256), переполнение считается отдельно и не таймится.
Часы: QPC по умолчанию (подтверждено: частота 10 МГц, двойной замер ~40 нс;
при 5.3 тыс. вызовов/с — шум). rdtsc не потребовался.
Команды: TickProf.bptrace.report (топ-20 по вызовам и по self-времени с долями,
мс/вызов в мкс), TickProf.bptrace.reset, TickProf.bptrace.caller <ранг|подстрока>.
[ДОБ] Приёмка дополнена проверкой отката: bptrace 0 снимает все подмены
(подтверждено: снято N, «скриптовых=0» в перечислении после включает состояние).

П2: матрица сейвов (после П1).
[ИЗМ] Оконная привязка к автосейву: каденция на стенде ровно 15 мин, окно ставится
сразу после строки «save: запись .ark завершилась» — тогда окно гарантированно
вне сейва (в слоте D 2 из 6 окон A/B были CONTAMINATED как раз из-за сейва).
[ИЗМ] По решению владельца Server2 в матрицу НЕ входит (сейв прод не снимается;
матрица: Genesis (стенд, плотная), TheIsland, Fjordur).
[ДОБ] Нормировка: вызовов/с и self-мс/с на 1000 акторов; для каждой карты —
census (число акторов/компонентов) сразу после окна.
[ДОБ] Прогрев вторичных карт может быть сокращён до 6–7 мин (вместо 10), если
окно ставится позже первого автосейва — отмечать в отчёте отдельно.

П3: атрибуция вызывающего InitializeLandingVariables.
[ИЗМ] Имя члена в этой сборке — FFrame::PreviousFrame, смещение +0x70
(подтверждено Ghidra: конструктор FFrame @0x141FA57E0, поле PreviousFrame;
Node = +0x10; Object = +0x18). CallFunction @0x141FBFEF0 создаёт новый кадр с
PreviousFrame = кадр вызывающего; верхний вход из ProcessEvent даёт 0 —
механизм директивы рабочий без изменений.
[ДОБ] Если у лидера вызывающий — 100% native/ProcessEvent-entry, это валидный
ответ (функцию зовёт нативный код, а не BP); указать в отчёте и искать
нативного автора через Ghidra отдельно.

П4: троттлинг через UFunction::Func (подготовка + осторожный выкат).
[ДОБ] Смещения для проверки return/out подтверждены Ghidra: UStruct+0x38 =
цепочка свойств, FProperty+0x28 = Next, FProperty+0x38 = флаги (uint32);
бит 0x80 = Parm, 0x100 = OutParm, 0x400 = ReturnParm. Команда
TickProf.fnflags <подстрока> печатает parms/out/return и вердикт
БЕЗОПАСНО/ЗАПРЕЩЕНО. Включение одной функции — только после A/B ≥2 валидных пар
и живого чеклиста поведения (птицы садятся, паук-бафф жив, миссии не падают);
сеанса с игроком нет — троттлинг в прод НЕ включать.

П5: мониторинг.
[ИЗМ] Реализовано как «правило тишины: 60 с блокировки команд измерения после конца
сэмплер-окна» (cooldown с записью в лог; срабатывание видно строкой
«cooldown: пауза 60 с ...»). Отказ команды в паузе пишется в лог («отказ -
пауза не кончилась»).

П6: trim3 живое подтверждение — остаётся открытым (нужен сеанс игрока);
роль поддерживающая.

Выход/порядок/красные линии: без изменений. П4 при нехватке времени режется
первым; троттлинг без П1–П3 запрещён.
