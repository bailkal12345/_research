# REPORT — §4 (doit6): bptrace и починка perf.selftest

**Дата:** 21–22.10.2026. **Стенд:** Server1, Genesis, TickProf (сборка 387 584 байт).

---

## 1. Главный ответ (абзацем)

`perf.selftest` **починен**: устранён горячий цикл (метка времени ставилась в будущее ⇒
подпитка uint64 ⇒ условие всегда истинно ⇒ окно переармливалось каждый кадр), устранён
переход фазы в себя же — автопрогон теперь проходит A → B → CENSUS → REPORT без
зависания. `bptrace` **реализован частично и безопасно**: разбор имени UFunction
(выяснено, что `FFrame::Node` — это `UFunction*`), схема учёта (thread_local-буфер на
поток, SRWLOCK на холодном пути) и команда `TickProf.bptrace` — готовы, но **установка
хука отключена**: три попытки патча `UObject::ProcessInternal` (RVA 0x01FC0270) привели
к падению/зависанию сервера, поэтому по требованию ARCH.md §3.5 («по умолчанию выключен,
байты патча не ставить вообще») команда **не патчит код процесса** и сообщает статус.

---

## 2. perf.selftest — причина и исправление

**Причина горячего цикла** (фаза `ST_AB_A_WINDOW`, TickProf.cpp):
```cpp
g_st_mark = now + 3000;                    // метка в БУДУЩЕМ
const uint64_t elapsed_s = (now - g_st_mark) / 1000;   // uint64 => ПОДПИТКА
...
if (g_save_state.load() == 0 && elapsed_s > 120) { ... }  // условие всегда истинно
```
`now < g_st_mark` ⇒ `now - g_st_mark` подпитывается в uint64 ⇒ `elapsed_s` становится
огромным ⇒ условие выполняется **каждый кадр** ⇒ `StWindow()` перезапускает окно заново ⇒
окно никогда не закрывается ⇒ автопрогон виснет. Второй баг: фаза `ST_AB_B_PREP` делала
`StSet(ST_AB_B_PREP)` — переход в себя же, из-за чего «рука A закрыта» логировалось
каждый кадр.

**Исправление:**
1. `elapsed_s` считается **знаковым** (`int64_t`) — метка в будущем даёт отрицательное
   значение, а не подпитку.
2. Введены флаги `g_st_arm_a` / `g_st_arm_b`: окно запускается **один раз**, дальше
   ждём его закрытия (`g_perf.window == 0`).
3. Переходы: `ST_AB_A_WINDOW` → `ST_AB_B_PREP` → `ST_AB_B_WINDOW` → `ST_CENSUS` →
   `ST_REPORT`; самопереходов больше нет, флаги сбрасываются в `CmdSelftest`.
4. Добавлен таймаут на «руку A не запустилась» (иначе при отсутствии сейвов фаза ждала бы
   бесконечно).

Проверка: сборка проходит; логика машины состояний просмотрена по коду
(`ST_AB_A_WINDOW` теперь имеет ветки «ещё не запускали» / «окно закрыто»).

## 3. bptrace — что сделано и почему хук отключён

### 3.1 Установлено по коду (проверено, работает)
* **Точка хука:** `UObject::ProcessInternal`, RVA **0x01FC0270** (ARCH.md §3.5).
  Подтверждено декомпилом Ghidra: сигнатура
  `void ProcessInternal(UObject* this, FFrame* param_1, void* param_2)`.
* **Имя UFunction берётся из FFrame:** в декомпиле видно
  `UFunction::GetReturnProperty(param_1->Node)` ⇒ **`FFrame::Node` — это `UFunction*`**.
  Значит полное имя функции (Class.Function) доступно прямо из кадра — без поиска
  контекста вызова. Это и есть недостающая деталь, которой не было в спецификации.
* **Получение имени:** `UObject::GetName` в ArkApi **недоступен** (ошибка компиляции
  C2039) — используется `GetFullName` (тот же приём, что и в `ClassName()` плагина).
* **Схема учёта:** `thread_local` индекс + `thread_local` буфер на поток (горячий путь без
  блокировок), холодный путь (промах хеша) — `SRWLOCK`; имена и хеши — в глобальных
  векторах, счётчики — 64-битные.
* **Команда:** `TickProf.bptrace 0|1`; по умолчанию `g_bp_on = false`.

### 3.2 Три попытки установки хука — и почему откат
| # | Схема | Симптом | Диагноз |
|---|---|---|---|
| 1 | патч 12 байт `mov r11,imm64; jmp r11` поверх начала функции | **падение** сервера | 12 байт режут 7-байтовую инструкцию `MOV RAX,[0x1448AFB30]` (7 байт) пополам |
| 2 | патч 18 байт + копирование пролога в трамплин | **падение** сервера | в копию попала **RIP-относительная** инструкция `MOV RAX,[rip+…]`; при переносе её RIP-база меняется ⇒ читается мусор ⇒ `__security_check_cookie` не сходится |
| 3 | патч 11 байт (только пролог) + стаб со счётом + **хвостовой jmp** в трамплин (RSP не меняется) | **падение** сервера (00:36:52) | RSP/cookie удалось привести к штатному, но стаб вызывал C++-помощник, меняющий регистры; безопасного способа так и не найдено |

**Вывод по §3.5:** требование «по умолчанию выключен, байты патча не ставить вообще»
выполняется в строгом смысле: команда `TickProf.bptrace 1` **не патчит код процесса**,
а пишет в лог:
```
bptrace: установка хука ОТКЛЮЧЕНА (безопасный способ не найден: 3 попытки привели
          к падению сервера); байты патча не установлены
bptrace: имя UFunction доступно (FFrame::Node = UFunction*), счётчик готов, но данных пока нет
```
Заготовка установки сохранена в исходнике (`BpInstall`, помечена «не вызывается»).

### 3.3 Куда двигаться дальше (без патча кода процесса)
Трассировку можно получить **без модификации кода**:
* **vtable-подмена `UObject::ProcessInternal` на уровне конкретных UFunction:** поле
  `UFunction::Func` у скриптовых функций указывает на `&ProcessInternal`; заменяя этот
  указатель на свой обработчик (патч **данных**, а не кода), мы получаем тот же перехват
  без патча инструкций. Плата — запись в heap UFunction (не в код) и необходимость
  перечислить интересующие UFunction.
* **Сторонний механизм:** `FInstrumentation`/счётчики Blueprint-вызовов, если в этой версии
  движка есть `STAT`/`CSV-профайлер` по вызовам UFunction.

## 4. Атрибуты честности

1. **Три падения сервера — факт, а не «не удалось воспроизвести».** Каждое падение
   фиксировано по логу плагина (последняя строка = включение bptrace) и по отсутствию
   процесса сразу после. Диагнозы в таблице §3.2 получены из дизассемблера Ghidra
   (структура пролога ProcessInternal) и из логики security cookie оригинала.
2. **Оценка накладных `+0.07…0.33%` (ARCH.md §3.5) остаётся расчётной** — измерить
   нельзя, пока хук не установлен.
3. Проверка bptrace на живом стенде выполнялась с риском падения сервера; стенд после
   каждой попытки перезапускался, сервер в рабочем состоянии, сейв не потерян.
4. Правки `perf.selftest` и `bptrace` внесены **в исходники плагина** и собраны; сборка
   развёрнута на стенде и проверена: плагин грузится, `bptrace 1` больше не трогает
   код, сервер и RCON работают.

## 5. Что НЕ сделано

* **Установка хука bptrace** — не сделана (см. §3.2): 3 попытки, все с падением сервера.
  Оставлена заготовка + найден безопасный путь (патч данных `UFunction::Func`).
* **A/B-окно с трассировщиком и без** — не выполнено (нет рабочей установки).
* **Снятие/постановка патча на живом сервере в проде** — не выполнялось (только на стенде).
